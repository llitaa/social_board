## 1. Answer in one paragraph

All seven refinements are accepted. Two of them changed after reading the code: the metrics importer cannot match a personal-profile export today (it needs a post title that LinkedIn's personal export does not contain), so "automatic numbers" is not true until that is fixed; and the learn stage learns only from Anton's notes, never from results, so the editorial review is a new function inside learn.py, not an extension of what exists. Everything below is split into immediate fixes (no experiment, about one day) and two controlled experiments (series, editorial review).

## 2. What the code actually does today

| Stage | Verified behaviour | Gap for the plan |
|---|---|---|

Adding three keys to the JSON answer is a prompt change plus one line in the stored metadata. |

## 4. Experiments (each with a stop rule)

| # | Experiment | Setup | Measure | Stop or continue |

| E1 | Series "Nach dem Go-live", two episodes | Episode 1 on the next Monday from the candidates E or F (Anton picks), episode 2 on the Friday after from C or D. Import via `import_draft.py` with the rendered PNG; `episode.py` is not built for two episodes. | Comments from relevant people, substantive replies, DMs or conversations that reference the episode, all written into inbound-log and posts-log by hand. Continue with episodes 3 to 6 only if at least one episode produced a substantive exchange. Otherwise Mon and Fri return to the normal personal slots and the engagement rule in config.yaml is switched off. |
| E2 | Editorial review inside learn.py | New function `review()` in `pipeline/learn.py`, called from process.py only when at least six published posts have numbers newer than the last review. Input: posts-log rows with numbers, the drafts' reader, insight, discussion_reason, pillar, format, and the comment counts. Output: `library/reviews/YYYY-MM-DD.md`, one page: which topics drew relevant discussion, which hooks or formats appeared to work, which posts underperformed against comparable posts, what to try in the next batch. Each statement labelled observed or hypothesis. The review is appended to the draft prompt as "Letzte Redaktionsnotiz" (the last one only). It never writes to positioning.md or style-rules.txt. One Sonnet call per review. | Anton reads the review (one page) and deletes lines he disagrees with, like style-rules today. | After two reviews: keep if at least one review changed what he approved; otherwise remove the prompt injection and keep the file for his own reading. |
